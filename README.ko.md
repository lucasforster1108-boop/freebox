# FreeBox —— 무료 VPS 한 대로 셀프호스팅 기지 전체를

"무료 ARM 머신을 잡았다"와 "그게 실제로 일을 한다" 사이의 간극에 질렸습니다. 튜토리얼은 전부 빈 Ubuntu 앞에서 끝납니다. FreeBox는 머신을 잡은 뒤 제가 설치하는 바로 그 한 세트입니다. 제 무료 머신에서 몇 달째 실제로 돌고 있는 시스템을 명령어 하나로 묶었습니다.

- **AdGuard Home**: 네트워크 전체의 광고와 트래커를 걸러내는 필터링 DNS
- **SubHub**: x-ui 노드에서 프록시 구독 링크를 자동 생성. 공유 링크를 손으로 고치는 시대는 끝
- **상태 페이지**: 지표, 서비스 점검, 휴대폰에서 누를 수 있는 컨트롤 버튼
- **Uptime Kuma**: 모니터링 + Telegram 알림. 서비스가 죽으면 휴대폰으로 바로 알림
- **주간 백업**: 묶어서 sha256으로 검증하고, 나눠서 머신 밖으로 전송. 남기는 건 최근 4개뿐
- **Cloudflare 터널**: 모든 서비스에 도메인과 HTTPS, **인바운드 포트는 하나도 열지 않음**

## 빠른 시작

필요한 것: 깨끗한 Debian/Ubuntu VPS 한 대(ARM이든 x86이든, 대부분 모듈은 메모리 1GB로 충분), root, 선택 사항으로 Cloudflare에 올려둔 도메인.

```bash
git clone https://github.com/<you>/freebox.git
cd freebox
cp config.example.env config.env   # 본인의 도메인과 토큰을 채우기
sudo ./install.sh                  # 전체 모듈
# 일부만 설치하려면:
sudo ./install.sh adguard subhub backup
```

각 모듈은 따로 설치할 수도 있습니다. `modules/` 아래 각 폴더에 자체 README와 설치 스크립트가 있습니다.

## 모듈 한눈에 보기

| 모듈 | 얻는 것 |
|---|---|
| `adguard` | AdGuard Home 원커맨드 배포 + 제거 |
| `subhub` | 구독 생성/배포: 노드를 JSON에 한 번만 적으면 `/토큰`과 `/토큰/<그룹>` 두 종류의 주소 제공. 원격 노드 DB는 scp로 가져오고 실패하면 자동으로 캐시 사용 |
| `status` | 제가 실제로 쓰는 상태 페이지(수집기 + 웹페이지 + 선택 사항 컨트롤 API) |
| `monitor` | Docker판 Uptime Kuma. 로컬에만 바인딩하고 Telegram 알림 설정 단계 포함 |
| `backup` | rclone 기반 주간 백업: 패키징 + sha256 + 400M 분할 + 최근 4개만 유지 |
| `tunnel` | cloudflared 설치 + ingress 템플릿 + 제가 추천하는 Access 게이트 방식 |

## 왜 이 구성인가

무료 머신이 고장 나는 방식은 대체로 정해져 있습니다. 위에서 뭐가 도는지 잊어버리고(상태 페이지), 한밤중에 조용히 죽고(모니터링), 백업이 디스크를 채우고(로테이션), 인증서 갱신 한 번에 HTTPS 사이트가 전부 동시에 죽고(인증서 체인, 아래 참조), 노드 하나 바뀌면 구독 링크가 전부 썩습니다(SubHub). FreeBox는 도구 여섯 개를 한 상에 모아놓은 게 아니라, 실제로 돈을 치르고 얻은 흉터입니다.

## 미리 내둔 수업료

- **인증서**: 어떤 ACME 방식은 리프 인증서만 설치합니다. 갱신 후 브라우저에서는 정상으로 보여도 엄격한 검증은 전부 떨어집니다. 전체 인증서 체인을 쓰세요.
- **cron과 시간대**: 시스템 시간대를 바꿔도 cron은 재시작하기 전까지 옛 시간대로 일을 보낼 수 있습니다. 작업이 돌았는지는 crontab 항목이 있는지가 아니라 결과 파일로 판단하세요.
- **백업**: 1G가 넘는 아카이브를 Google Drive에 통째로 올리지 마세요. 중간에 끊깁니다. 나눠서 올리고(백업 모듈 기본값 400M), 조각마다 크기를 확인하고, 목적지를 두 곳 두세요.
- **웹 설정 디렉터리**: 백업 파일을 와일드카드로 include되는 디렉터리(예: `sites-enabled/`) 안에 절대 두지 마세요. 삭제한 서비스가 자기 백업에서 "부활"합니다.
- **저메모리 머신**: 한 번에 하나만 설치하고, 설치할 때마다 `free -h`를 확인하세요. 희망은 메모리 관리 전략이 아닙니다.

## 보안 안내

- 서비스는 가능한 한 `127.0.0.1`에만 바인딩하고, 문은 터널에 맡기세요.
- SubHub 토큰은 비밀번호입니다. 상태 페이지의 컨트롤 API는 반드시 인증 뒤에 두고, 관리용 입구에는 Cloudflare Access를 권장합니다.
- `config.env`, 토큰, 노드 DB는 전부 gitignore 처리되어 있습니다. 손으로 커밋하지 마세요.
