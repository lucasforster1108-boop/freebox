# 服务器一键备份脚本

把服务器上的重要目录自动打包、校验、上传到网盘，并自动清理旧备份。
跑一次命令（或挂上定时任务）就能完成一整套备份，不用再手动拖文件。

## 功能

- 📦 **自动打包**：把配置里列的目录打成一个带日期的 `.tar.gz` 压缩包
- 🔪 **大文件自动分块**：压缩包超过设定大小（默认 400M）自动切成小块再上传，避免大文件直传失败
- ✅ **完整性校验**：每份备份都生成 sha256 校验文件，恢复时能验证文件有没有损坏
- ☁️ **上传网盘**：通过 rclone 上传，支持 Google Drive、OneDrive 等所有 rclone 支持的网盘
- 🧹 **自动清理**：只保留最近 4 份（可在配置里改），旧的自动删除，不怕把网盘塞满
- 📝 **全程日志**：每一步都有输出并写进日志文件，出问题能查到是哪一步
- 🔁 **可重复运行**：中途失败直接重新运行即可，不会把已有的备份弄乱

## 使用方法（三步）

### 第 1 步：安装 rclone 并授权网盘

在服务器上执行：

```bash
curl https://rclone.org/install.sh | sudo bash   # 安装 rclone
rclone config                                      # 创建 remote
```

`rclone config` 里选 `n`（新建），名字随便起、记住它（比如 `mydrive`，要和第 2 步配置里填的一致），类型选你的网盘（例如 Google Drive 选 `drive`），之后按提示在浏览器里登录网盘完成授权。

授权完测试一下，能列出网盘目录就说明通了：

```bash
rclone lsd mydrive:
```

### 第 2 步：改配置

```bash
cp backup.conf.example backup.conf
nano backup.conf    # 或用你顺手的编辑器
```

只需要改三个必填项：

| 配置项 | 填什么 |
|---|---|
| `SOURCE_DIRS` | 要备份的目录，如 `/etc`、你的网站目录、数据目录 |
| `REMOTE_NAME` | 第 1 步在 rclone config 里起的 remote 名字 |
| `REMOTE_PATH` | 网盘上放备份的目录，如 `backups/my-server`，不存在会自动创建 |

保留份数（`KEEP_COUNT`，默认 4）和分块大小（`SPLIT_SIZE`，默认 400M）一般不用改。

### 第 3 步：手动跑一次验证

```bash
chmod +x backup.sh
./backup.sh
```

看终端输出：每一步都会打印进度，最后出现「备份成功」就对了。
再去网盘里确认：`REMOTE_PATH` 目录下应该多了一个 `backup-年月日-时分秒` 文件夹，里面是压缩包（或分块文件）和一个 `.sha256` 校验文件。日志同时写在脚本目录的 `logs/backup.log` 里。

## 挂 cron 每周自动跑

手动验证成功后，执行 `crontab -e`，加一行（意思：每周日凌晨 3:23 自动备份，路径换成你脚本的实际位置）：

```cron
23 3 * * 0 /path/to/vps-backup/backup.sh
```

脚本自己会写日志，不用再加重定向。之后每周去 `logs/backup.log` 看一眼有没有「备份成功」即可。

## 恢复备份

1. 把某一份备份从网盘下载到本地：

   ```bash
   rclone copy mydrive:backups/my-server/backup-20260101-032300 ./restore
   cd restore
   ```

2. 如果里面是分块文件（文件名带 `.part-000`、`.part-001`……），先合并成完整压缩包。合并后的文件名要和 `.sha256` 文件里记录的名字一致（就是去掉 `.part-000` 后缀的那个名字）：

   ```bash
   cat backup-20260101-032300.tar.gz.part-* > backup-20260101-032300.tar.gz
   ```

   （没有分块、直接就是 `.tar.gz` 的，跳过这一步。）

3. 校验完整性，显示 `OK` 才继续：

   ```bash
   sha256sum -c backup-20260101-032300.tar.gz.sha256
   ```

4. 解压恢复。压缩包里存的是去掉开头 `/` 的路径，解压到根目录即恢复到原位置（请先确认这正是你想要的，解压会覆盖同名文件）：

   ```bash
   sudo tar -xzf backup-20260101-032300.tar.gz -C /
   ```

## 常见问题

**1. 为什么大文件要切成 400M 的小块？**
很多网盘对单个文件的上传有大小或时长限制，一个几个 G 的大文件直传很容易中途失败，失败了还得整个重传。切成小块后，每块独立上传，某块失败只需要重传那一块；而且 rclone 重新运行时会跳过已经传好的块，省时省流量。400M 只是默认值，你的网盘如果没这个限制，可以在 `backup.conf` 里把 `SPLIT_SIZE` 调大或调小。

**2. 运行时报错说找不到 remote，或者以前能传、现在传不上？**
多半是网盘授权（token）过期了。执行 `rclone config reconnect mydrive:` 重新授权一次即可。remote 名字也要和配置里的 `REMOTE_NAME` 完全一致，先用 `rclone listremotes` 核对。

**3. 备份会占多少网盘空间？想多留几份怎么办？**
大约是「单份压缩包大小 × 保留份数」。改 `backup.conf` 里的 `KEEP_COUNT` 即可，比如改成 8 就保留最近 8 份。注意免费网盘空间有限，别设太大。

**4. 打包时报磁盘空间不足？**
脚本是先在本地临时目录（`WORK_DIR`，默认 `/tmp/vps-backup-work`）里生成完整压缩包再上传的，所以本地要预留至少「源数据压缩后大小」的空闲空间。解决办法：清理本地磁盘，或在 `backup.conf` 里把 `WORK_DIR` 改到空间大的磁盘上。
