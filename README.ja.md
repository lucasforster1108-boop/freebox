# FreeBox —— 無料 VPS 1 台で、セルフホスト基地をまるごと

「無料の ARM マシンを確保した」と「それが実際に役に立つ」の間にある溝にうんざりしました。チュートリアルはどれも、まっさらな Ubuntu の前で終わります。FreeBox は、確保したマシンの後に私が入れる一式です。自分の無料マシンで数か月実稼働してきたシステムそのものを、1 つのコマンドにまとめました。

- **AdGuard Home**：ネットワーク全体の広告とトラッカーを消すフィルタリング DNS
- **SubHub**：x-ui のノードからプロキシ購読リンクを自動生成。共有リンクを手で直す時代は終わり
- **ステータスページ**：指標、サービスのチェック、スマホから押せるコントロールボタン
- **Uptime Kuma**：監視 + Telegram アラート。サービスが落ちたらスマホに直接届く
- **週次バックアップ**：パックして sha256 で検証し、分割してマシンの外へ。残すのは直近 4 世代だけ
- **Cloudflare トンネル**：全サービスにドメインと HTTPS、**インバウンドポートは 1 つも開けない**

## クイックスタート

必要なもの：きれいな Debian/Ubuntu VPS 1 台（ARM でも x86 でも可、たいていのモジュールはメモリ 1GB で足ります）、root、任意で Cloudflare に置いたドメイン。

```bash
git clone https://github.com/<you>/freebox.git
cd freebox
cp config.example.env config.env   # 自分のドメインとトークンを入れる
sudo ./install.sh                  # 全モジュール
# 一部だけなら：
sudo ./install.sh adguard subhub backup
```

各モジュールは単体でも入れられます。`modules/` の各フォルダに、それぞれの README とインストールスクリプトがあります。

## モジュール一覧

| モジュール | 得られるもの |
|---|---|
| `adguard` | AdGuard Home のワンコマンド導入 + アンインストール |
| `subhub` | 購読の生成と配布：ノードを JSON に一度書けば `/トークン` と `/トークン/<グループ>` の 2 種類のアドレスが得られる。リモートのノード DB は scp で取得し、失敗したら自動でキャッシュにフォールバック |
| `status` | 私が実際に使っているステータスページ（コレクター + Web ページ + 任意のコントロール API） |
| `monitor` | Docker 版 Uptime Kuma。本体にはバインドせず、Telegram 通知の設定手順付き |
| `backup` | rclone ベースの週次バックアップ：パック + sha256 + 400M 分割 + 直近 4 世代だけ保持 |
| `tunnel` | cloudflared の導入 + ingress テンプレート + 私が勧める Access の門番設定 |

## なぜこの構成か

無料マシンの壊れ方はだいたい決まっています。上で何が動いているか忘れる（ステータスページ）、夜中に静かに死ぬ（監視）、バックアップがディスクを埋める（ローテーション）、証明書の更新 1 回で HTTPS の全サイトが同時に落ちる（証明書チェーン、下記参照）、ノードが変わると購読リンクが全部腐る（SubHub）。FreeBox はツールを 6 個寄せ集めたものではなく、実害を食らってできた傷跡です。

## 先に払っておいた授業料

- **証明書**：ACME の導入方法によっては、リーフ証明書しかインストールされません。更新後、ブラウザでは正常に見えても厳格な検証は全部落ちます。完全な証明書チェーンを使ってください。
- **cron とタイムゾーン**：システムのタイムゾーンを変えても、cron は再起動するまで旧タイムゾーンで動き続けることがあります。タスクが走ったかどうかは crontab の有無ではなく、生成物ファイルで判断してください。
- **バックアップ**：1G を超えるアーカイブを Google Drive に一括で上げないでください。途中で切られます。分割し（バックアップモジュールは既定 400M）、塊ごとにサイズを確認し、保存先を 2 つ持ちましょう。
- **Web の設定ディレクトリ**：バックアップファイルを、ワイルドカードで include されるディレクトリ（`sites-enabled/` など）には絶対に置かないでください。削除したサービスが自分のバックアップから「復活」します。
- **小メモリのマシン**：1 回に 1 モジュールだけ入れ、入れるたびに `free -h` を確認。希望はメモリ管理戦略ではありません。

## セキュリティ

- サービスはできるだけ `127.0.0.1` にだけバインドし、門はトンネルに任せます。
- SubHub のトークンはパスワードです。ステータスページのコントロール API は必ず認証の後ろに置き、管理系の入口には Cloudflare Access を勧めます。
- `config.env`、トークン、ノード DB はすべて gitignore 済みです。手でコミットしないでください。
